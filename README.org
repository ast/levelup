#+title: levelup
#+author: Albin Stigö
#+options: toc:nil num:nil

A Rust workspace of six personal-computing tools, named from Norse mythology:

- *munin* — atuin-like shell-history search with an fzf-style TUI. Daemon + CLI + interactive picker, fuzzy matching via [[https://crates.io/crates/nucleo-matcher][nucleo-matcher]], SQLite storage.
- *hugin* — Wayland clipboard manager for sway / wlroots compositors. Captures every selection change to a local SQLite DB, with fuzzy search and an interactive picker of its own.
- *mimir* — a compact, interactive status bar for sway (an i3status replacement). Three clocks + power-user system metrics, read straight from =/proc= & =/sys=.
- *sleipnir* — a modeless frecency navigator. Fuses fzf's file-finder, jump-to-folder, and =z= into one Ctrl-T picker over the directories *and* files you actually use.
- *valkyrie* — a modeless, humane process finder/handler. Alt-P opens a live picker; type to filter (incl. =:port=), act with graceful-first signals.
- *heimdall* — a rootless LAN device finder. Who's on your network right now, via ARP-sweep + mDNS + SSDP + OUI, all in user space (no root).

The five interactive pickers (munin, hugin, sleipnir, valkyrie, heimdall) share one design language: a modeless fuzzy search over a single content space (type to narrow everything at once), fzf-style layout with the prompt on the bottom row, =‹match›= highlighting in the match colour, and a readline/Emacs editing keymap. Built in the spirit of Jef Raskin's *Humane Interface* and Don Norman's *Design of Everyday Things*.

All crates target Rust 2024 (resolver 3), share workspace dependencies, and are built independently.

* Requirements

- Rust 1.85+ (edition 2024).
- For hugin: a wlroots-based Wayland compositor (sway, hyprland, river). =wlr-data-control-unstable-v1= is *not* implemented by GNOME or KDE.
- =wl-clipboard= (=wl-copy=, =wl-paste=) for hugin's smoke-test recipe.
- =just= (optional, for the workspace recipes — see [[file:justfile][justfile]]).

* munin

A shell-history daemon (=munind=) and CLI (=munin=) that captures every command you run, indexes it for fuzzy search, and exposes an fzf-style interactive picker on Ctrl-R.

** Install

#+begin_src sh
cargo build --release -p munin
install -Dm755 target/release/munind ~/.local/bin/munind
install -Dm755 target/release/munin  ~/.local/bin/munin
#+end_src

That's the whole install — there is no systemd unit to set up. The =munin= CLI owns the daemon's lifecycle: any command that needs =munind= (currently =import=, and sync later) starts it automatically and race-free, so it "just works". You can also drive it explicitly:

#+begin_src sh
munin daemon start     # start it now (idempotent — no-op if already up)
munin daemon status    # running? pid, uptime, db + socket paths
munin daemon stop      # graceful shutdown
munin daemon restart   # stop (if up) then start fresh, e.g. after upgrading
munin daemon ping      # liveness probe: "ok" / "not running" (exit 1); never starts it
#+end_src

The daemon listens on =$XDG_RUNTIME_DIR/munin.sock=, writes to =$XDG_DATA_HOME/munin/munin.db= (default =~/.local/share/munin/munin.db=), and logs to =$XDG_STATE_HOME/munin/munind.log= (default =~/.local/state/munin/munind.log=) when auto-started.

*Migrating from a previous systemd setup:* earlier versions shipped a =munind.service= user unit. If you enabled it, disable it so systemd and the CLI don't both manage the daemon:

#+begin_src sh
systemctl --user disable --now munind
rm -f ~/.config/systemd/user/munind.service
#+end_src

** Shell setup

Add to =~/.zshrc=:

#+begin_src sh
eval "$(munin init zsh)"
#+end_src

…or to =~/.bashrc=:

#+begin_src sh
eval "$(munin init bash)"
#+end_src

This wires up two things:

1. *Capture hooks* — every command you run is recorded (cmd, cwd, hostname, session, shell, exit code, duration). Commands prefixed with a space are skipped on zsh (the standard =HIST_IGNORE_SPACE= convention).
2. *Ctrl-R picker* — replaces your shell's native history search with the munin TUI:
   - *Enter* → splice and run the chosen command (zsh only; see bash caveat below).
   - *Tab* → splice the command onto the prompt for editing, don't run.
   - *Esc* / *Ctrl-C* → leave the prompt untouched.

The TUI bypasses the daemon and reads SQLite directly, so it works even if =munind= is down.

*Bash caveat:* =bind -x= (the only way to wire a Rust binary into readline) cannot trigger Enter from inside the bound function. On bash, both Enter and Tab in the picker land the chosen command on the prompt and you hit Enter yourself to run it. zsh honours the run/edit distinction natively.

*Shell completions* (optional) — =munin completions [SHELL]= prints a completion script to stdout (=clap_complete=). SHELL defaults to =$SHELL=; pass one explicitly for any of bash/zsh/fish/elvish/powershell:

#+begin_src sh
munin completions zsh  > ~/.zfunc/_munin            # then ensure ~/.zfunc is on $fpath
munin completions bash > ~/.local/share/bash-completion/completions/munin
munin completions fish > ~/.config/fish/completions/munin.fish
#+end_src

** Importing existing history

#+begin_src sh
munin import atuin                       # from ~/.local/share/atuin/history.db
munin import atuin --path /custom/path   # override
munin import zsh   ~/.zsh_history
munin import bash  ~/.bash_history
#+end_src

Imports go through the daemon (writes serialize through the storage thread). Re-imports are idempotent — atuin's UUIDv7 ids are preserved as munin's =uuid=, and shell-history files dedupe on the same key.

** Searching from the CLI

These don't need the daemon — they open SQLite directly:

#+begin_src sh
munin search gcm                         # fuzzy: matches "git commit -m …"
munin search "cargo test" --limit 20
munin list --limit 20                    # most-recent first
munin list --cwd "$PWD" --shell zsh
munin get 1234                           # one entry's metadata
#+end_src

Filters available on =list= / =search=: =--cwd=, =--session=, =--shell=, =--since=, =--until= (=YYYY-MM-DD= or =YYYY-MM-DD HH:MM:SS=, local time), =--limit=.

=munin search -i [QUERY]= opens the interactive TUI seeded with the query — same picker the Ctrl-R hook invokes.

** Config

Optional TOML file at =$XDG_CONFIG_HOME/munin/config.toml=. All keys default if absent; bad TOML logs a warning and falls back to defaults (the TUI never refuses to open over a config error).

#+begin_src toml
sort   = "relevance"     # "relevance" | "recent"
limit  = 200             # rows fetched per keystroke
layout = "bottom"        # "bottom" (fzf-style) | "top"

[colors]
selection_fg = "black"
selection_bg = "cyan"
match_fg     = "yellow"
prompt_fg    = "green"
status_fg    = "gray"
#+end_src

Colours accept the named ANSI palette (=black=/=red=/.../=gray=/=darkgray=/=light*=).

** Daemon vs CLI — what needs the daemon

Captures and reads all open SQLite directly, so they work whether or not =munind= is running. Only bulk =import=, the liveness probe, and the daemon-control ops use the socket — and those start the daemon on demand:

| Command                             | Path            | Needs daemon?        |
|-------------------------------------+-----------------+----------------------|
| =munin add-start= / =munin add-end= | direct SQLite   | no (capture hot path) |
| =munin list= / =search= / =get=     | direct SQLite   | no                   |
| =munin search -i= (TUI)             | direct SQLite   | no                   |
| =munin init <shell>=                | embedded script | no                   |
| =munin completions [SHELL]=         | embedded script | no                   |
| =munin import=                      | unix socket     | yes — auto-starts    |
| =munin daemon start/stop/status/restart= | unix socket | manages it directly  |
| =munin daemon ping=                 | unix socket     | no — pure probe      |

WAL mode makes concurrent reads/writes safe alongside the daemon.

** Logging

=tracing= to stderr, gated by =MUNIN_LOG= (full =tracing-subscriber= EnvFilter syntax). Default is =info=.

#+begin_src sh
MUNIN_LOG=debug munind                  # foreground, verbose
tail -f ~/.local/state/munin/munind.log # follow an auto-started daemon's log
#+end_src

* hugin

Wayland clipboard manager for sway / hyprland / river (anything supporting =wlr-data-control-unstable-v1=). Persists every selection change to SQLite with dedup and retention. Both the *regular* selection (Ctrl-C / Ctrl-V) and the *primary* selection (mouse text selection / middle-click) can be tracked as independent streams. Honours the =x-kde-passwordManagerHint=secret= convention used by KeePassXC, Bitwarden, and 1Password to keep passwords out of history.

** Daemon (=hugind=)

A foreground process supervised by =systemd --user= (see below); run it directly from a shell during development.

#+begin_src sh
# Default DB at $XDG_DATA_HOME/hugin/hugin.db,
# socket at $XDG_RUNTIME_DIR/hugin.sock
cargo run --bin hugind -p hugin

# Override paths and crank up logging
HUGIN_LOG=debug ./target/release/hugind \
    --db /tmp/hugin.db --socket /tmp/hugin.sock
#+end_src

The primary selection is off by default (mouse-drag selection emits a steady stream of intermediate MIMEs); enable it with =--primary=. See =hugind --help= for retention flags (=--max-entries=, =--max-age-days=).

** CLI (=hugin=)

The =hugin= CLI talks to the running daemon over its unix socket. By default it connects to =$XDG_RUNTIME_DIR/hugin.sock=; pass =--socket PATH= to override.

| Subcommand                                              | What it does                                                                                                             |
|---------------------------------------------------------+------------------------------------------------------------------------------------------------------------------------|
| =hugin ping=                                            | Verify the daemon is responsive.                                                                                       |
| =hugin list [--limit N] [--selection regular\vert primary]= | Print recent entries, newest first.                                                                                |
| =hugin search QUERY [-i] [--sort relevance\vert recent]=    | Fuzzy-search history (=-i= opens the interactive picker).                                                           |
| =hugin info ID=                                         | Show metadata for one entry (timestamp, selection, MIMEs).                                                             |
| =hugin get ID [--mime MIME]=                            | Write the entry's contents to stdout. Default MIME is the first =text/*= advertised, falling back to the first available. |
| =hugin copy ID [--selection regular\vert primary]=          | Put an old entry back on the clipboard. The daemon becomes the data source until another app takes over.            |

Each subcommand has a short unix-style alias: =ls= (list), =s= (search), =stat= (info), =cat= (get), =cp= (copy), =comp= (completions). =hugin --help= shows them.

Examples:

#+begin_src sh
# What's in the recent history?
hugin list

# Just things selected with the mouse (primary), last 10
hugin list --selection primary --limit 10

# Fuzzy search: matches a "git commit -m …" clipping
hugin search gcm

# Inspect which MIME variants exist for an entry
hugin info 42

# Get the plain text…
hugin get 42

# …or the HTML the source app also offered
hugin get 42 --mime text/html

# Put an old entry back on the clipboard (daemon becomes the source)
hugin copy 42

# Same, but onto the primary selection
hugin copy 42 --selection primary
#+end_src

** Interactive picker

=hugin search -i= opens an fzf-style =ratatui= picker with a right-side preview pane:

- *Enter* → copy the whole entry to the clipboard.
- *Tab* → print the entry's content to stdout (pipe-friendly).
- *Ctrl-O* → choose a MIME variant, then copy it.
- *Ctrl-X* → delete the entry (after a =y=/=n= confirm).
- *Esc* / *Ctrl-C* / *Ctrl-G* → cancel.

Search and the preview read SQLite directly (the picker works with =hugind= down); copy and delete round-trip to the daemon and report failures in the status line. Config lives at =$XDG_CONFIG_HOME/hugin/config.toml= (same shape as munin's, plus a =preview= toggle).

** Running under systemd

For day-to-day use, run =hugind= as a user service tied to the graphical session. A ready-to-edit unit lives at [[file:dist/hugind.service][=dist/hugind.service=]] (it expects the binary at =~/.cargo/bin/hugind=, i.e. wherever =just install= puts it).

#+begin_src sh
just install
mkdir -p ~/.config/systemd/user
cp dist/hugind.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now hugind.service
journalctl --user -u hugind.service -f                     # tail logs
#+end_src

Sway needs to publish =WAYLAND_DISPLAY= into the user manager and activate the target. Add to =~/.config/sway/config=:

#+begin_src sh
exec systemctl --user import-environment WAYLAND_DISPLAY XDG_CURRENT_DESKTOP
exec systemctl --user start graphical-session.target
#+end_src

The unit uses =Type=notify=, so =systemctl --user start hugind= blocks until the daemon is ready. =PartOf=graphical-session.target= stops hugin when sway exits; =Restart=on-failure= retries transient errors (e.g. compositor restart) without thrashing.

To pass flags (=--primary= for instance), override the unit:

#+begin_src sh
systemctl --user edit hugind.service
# In the editor:
# [Service]
# ExecStart=
# ExecStart=%h/.cargo/bin/hugind --primary
#+end_src

* mimir

A compact, interactive status bar for sway — an =i3status= replacement. A single foreground process that swaybar spawns: it prints the swaybar/i3bar JSON protocol on stdout and reads click events on stdin. System state is read straight from =/proc= & =/sys= (parsed with [[https://crates.io/crates/nom][nom]]); the only other notable dependency is =chrono-tz= for named timezones. No daemon, no async runtime, no SQLite.

Blocks shipped in v1: a three-zone clock (Local / UTC / Natal-Brazil), CPU%, load average, memory + swap, disk usage, network throughput + wifi signal, temperature, battery, and CPU governor/frequency. Each is coloured by configurable warn/critical thresholds (turning *urgent* past critical) and prefixed with a Nerd Font glyph.

#+begin_example
Tue 02 Jun · LOC 11:45 · UTC 09:45 · NAT 06:45    1.2K ↑256K  / 23%   5.2G/16G   0.93 1.77 1.80   12%   62°C   85%   powersave 2.4GHz
#+end_example

** Install

#+begin_src sh
cargo build --release -p mimir
install -Dm755 target/release/mimir ~/.local/bin/mimir
#+end_src

A *Nerd Font* must be configured in your bar's font for the glyphs to render (or set =icons = "text"= in the config for ASCII labels).

** Sway integration

Point swaybar at =mimir= in =~/.config/sway/config=:

#+begin_src
bar {
    status_command mimir
    font pango:JetBrainsMono Nerd Font 10
}
#+end_src

Reload sway (=$mod+Shift+c=). Click a block to interact:

- *Left-click* expands a fuller view (CPU → per-core, memory → +swap, disk → free space, clock → seconds).
- *Scroll* and other buttons are reserved for future per-block actions.
- Bind a *command* to any (block, button) in the config (e.g. click the clock to open a calendar).

** CLI

| Subcommand            | What it does                                                            |
|-----------------------+-------------------------------------------------------------------------|
| =mimir=               | Run the bar (default).                                                   |
| =mimir once=          | Print a single plain-text snapshot and exit — handy for debugging.       |
| =mimir print-config=  | Emit the default =config.toml= (all keys documented).                   |
| =mimir completions [SHELL]= | Print a shell-completion script (alias =comp=; SHELL defaults to =$SHELL=). |

Pass =--config PATH= to override the config location.

#+begin_src sh
mimir once                 # one-line snapshot in a normal terminal
mimir print-config > ~/.config/mimir/config.toml
#+end_src

** Config

Optional TOML at =$XDG_CONFIG_HOME/mimir/config.toml=. All keys optional; a missing file or bad TOML falls back to defaults (the bar never refuses to start). Unknown keys are tolerated for forward-compatibility. Generate a fully-commented starting point with =mimir print-config=. Highlights:

#+begin_src toml
interval_ms = 1000           # global refresh tick
icons       = "nerdfont"      # "nerdfont" | "text"
order = ["clock", "net", "disk", "memory", "load", "cpu", "thermal", "battery", "power"]

[clock]
date_format = "%a %d %b"
zones = [
  { label = "UTC", tz = "UTC" },
  { label = "NAT", tz = "America/Fortaleza" },  # Natal, RN — UTC-3, no DST
]

[[bindings]]                 # click the clock → open a calendar
block = "clock"
button = 1
command = "gnome-calendar"
#+end_src

Thermal/CPU/memory/disk blocks each take =warn= / =critical= thresholds; the battery block reads them as "warn/critical when *below*". Colours are configurable under =[colors]=.

* sleipnir

A modeless frecency navigator that collapses three tools — fzf's file-finder, fzf's jump-to-folder, and =z= — into one =Ctrl-T= picker over a single list fusing the directories *and* files you actually touch.

** Install

#+begin_src sh
cargo build --release -p sleipnir
install -Dm755 target/release/sleipnir ~/.local/bin/sleipnir
#+end_src

** Shell setup

Add to =~/.zshrc=:

#+begin_src sh
eval "$(sleipnir init zsh)"
#+end_src

This adds a =chpwd= hook (records every directory you visit) and binds *Ctrl-T* to the picker.

Shell completions: =sleipnir completions [SHELL]= (alias =comp=; SHELL defaults to =$SHELL=).

** How it works

- *Directories* are ranked by frecency (frequency × recency, zoxide's decay curve) from the chpwd hook.
- *Files* come from two fused sources: a live, =.gitignore=-aware walk of the enclosing git repo (ranked by modification time, so a file you only edited in your editor still appears), and your *munin* command history (files you've named as arguments — so it ranks what you actually open). munin is optional; without it you still get the walk + dirs.

One modeless list — type and *everything* narrows at once. *Enter* on a directory =cd='s there; *Enter* on a file inserts its path on the command line; *Tab* is the inverse (file → its parent dir, dir → insert as an argument). A right-side preview pane shows a directory listing or a syntax-highlighted file head.

Storage at =$XDG_DATA_HOME/sleipnir/sleipnir.db=; config at =$XDG_CONFIG_HOME/sleipnir/config.toml= (=layout=, =preview=, and =[colors]= incl. =dir_fg= / =file_fg=).

* valkyrie

A modeless, humane process finder/handler — htop's reach without the modes. *Alt-P* opens a live picker over running processes (sorted by %CPU).

** Install

#+begin_src sh
cargo build --release -p valkyrie
install -Dm755 target/release/valkyrie ~/.local/bin/valkyrie
eval "$(valkyrie init zsh)"   # in ~/.zshrc: binds Alt-P, adds the `vk` alias
#+end_src

Shell completions: =valkyrie completions [SHELL]= (alias =comp=; SHELL defaults to =$SHELL=).

** Keys

Type to filter across name / cmdline / PID / user / *=:port=* in one search (=:3000= finds whatever's listening there). Letters feed the query, so every action is a Ctrl/Tab key:

| Key              | Action                                                          |
|------------------+----------------------------------------------------------------|
| =Enter=          | SIGTERM (graceful)                                             |
| *hold =Alt-K=*   | SIGKILL — a meter fills while held; release cancels            |
| =Ctrl-Z=         | SIGSTOP / SIGCONT toggle (pause / resume)                      |
| =Tab=            | signal chooser (curated set + type any name/number)            |
| =Ctrl-T=         | process *tree* — homogeneous broods (firefox ×12) auto-collapse |
| =Ctrl-O=         | scope: all ↔ mine                                             |
| =Ctrl-R=         | sort: cpu / mem / pid                                          |
| =Ctrl-V=         | toggle the detail strip                                        |
| =Esc= / =Ctrl-C= | quit                                                          |

The irreversible kill is gated behind a sustained physical gesture, never a yes/no dialog (Raskin). A horizontal detail strip shows the selected process's exe/cwd/ports/threads plus a calm aggregate CPU + load line. Reads =/proc= directly; no daemon, no storage.

* heimdall

A rootless LAN device finder — the all-seeing watchman. Discovers everything on your local network *in user space* (no root, no raw sockets) by combining a TCP/UDP subnet sweep that provokes the kernel's ARP cache with *mDNS* and *SSDP* multicast, plus an OUI vendor lookup.

** Install

#+begin_src sh
cargo build --release -p heimdall
install -Dm755 target/release/heimdall ~/.local/bin/heimdall
#+end_src

** Usage

#+begin_src sh
heimdall          # the live interactive picker
heimdall scan     # one-shot, non-interactive dump (IP / MAC / vendor / host / services)
heimdall init     # print a shell alias (`ht`)
heimdall completions [SHELL]   # completion script (alias `comp`; SHELL defaults to $SHELL)
#+end_src

The picker is *presence-first* — it shows who's reachable *right now*. Devices fill in live (names resolve asynchronously via mDNS/SSDP), each shows its last-seen age and *dims when it goes quiet*, dropping after a timeout. Type to fuzzy-filter across IP / MAC / vendor / hostname / service. A horizontal detail strip shows the selected device.

Actions on the selected device:

- *Enter* → open =http://IP= in your browser (=xdg-open=).
- *Ctrl-S* → ssh to it (suspends the picker, runs ssh, returns).
- *Ctrl-Y* → copy the IP to the clipboard (=wl-copy= / =xclip=).
- *Tab* → on-demand TCP port scan.

A small MAC-keyed cache at =$XDG_CACHE_HOME/heimdall/devices.db= makes relaunch instant (last-known devices show immediately, then confirm or drop by reachability). Config at =$XDG_CONFIG_HOME/heimdall/config.toml=.

*Rootless caveat:* a device that ignores TCP, advertises nothing on mDNS/SSDP, and isn't in the ARP cache won't appear — that's the price of running without raw sockets.
